## Problem
The build fails at the install step when Railpack runs `npm ci`. The error is:
```
npm error The `npm ci` command can only install with an existing package-lock.json or
npm error npm-shrinkwrap.json with lockfileVersion >= 1.
```
The SNAPSHOT stage completed successfully. The BUILD_IMAGE stage failed immediately during dependency installation. The install command (`npm ci`) comes from Railpack auto-detection — no custom build config is set (no railway.toml/railway.json, no dashboard overrides).

## Diagnosis
The `package-lock.json` file exists (244KB) and declares `lockfileVersion: 3`, but npm rejects it as invalid. The file was generated by Replit's environment (confirmed by `.replit`, `replit.nix`, and Replit Agent commit metadata). It contains `"requires": true` which is a lockfileVersion 1 field — this mixed format makes the lockfile structurally incompatible with standard npm's `npm ci` command, which performs strict validation. The triggering commit only changed WhatsApp session JSON files and did not modify `package.json` or `package-lock.json`, meaning the lockfile has been in this broken state prior to this deployment.

## Fix
This fix cannot be auto-applied because it requires running `npm install` to regenerate the lockfile (a command execution, not a text file edit).

**Option A (recommended): Regenerate the lockfile**
1. In a standard Node.js 18+ environment (not Replit), run `npm install` in the project root
2. Commit and push the updated `package-lock.json`

**Option B: Delete the lockfile**
1. Run `git rm package-lock.json`
2. Commit and push

Without a lockfile, Railpack will detect no lockfile and use `npm install` instead of `npm ci`, which does not require a pre-existing valid lockfile. Option A is preferred as it ensures reproducible builds.
